## Research practice (v1 — inherited from an earlier research loop, which earned these the hard way)
- **Synthetic-smoke before real data.** New analysis → run it on a tiny fake input with a *known* answer first; catch bugs in seconds.
- **Cite, don't claim.** Paste the exact output/CSV line before asserting any number (constitution §3).
- **Verify in both directions.** Don't assert without checking and don't doubt without checking — both are the same failure. The complementary cross-check (e.g. shuffle vs scrub) is what catches a confident wrong conclusion.
- **The auto-verdict lies.** A script's printed VERDICT has repeatedly mislabeled significance/sign/confounds. Read the raw numbers + CI + n yourself.
- **Measurement-floor ≠ null.** A flat result can be a resolution floor, not a true negative. Check the dynamic range / control fired.
- **Replicate selected positives on fresh seeds.** Borderline winners regress to the mean.
- **Toy/free compute = directional.** Label findings from `claude -p`/toy tasks as illustrative, not frontier numbers.
- **Winner's-curse SIMS are an UPPER BOUND; capable real agents self-correct (meth-14, cycle 36).** Our selection-bias sims assume NAIVE in-sample selection. A real `claude -p` agent on the same task self-applied CV + a conservative discount, AVOIDED the catastrophe (all-features OOS −0.19 → its model +0.054, near oracle), and beat the naive all-features model — so the sims are an UPPER BOUND for a naive selector (report magnitudes that way). **⚠️ Revised cycle 37 (n=4): the agent's calibration is MIXED-sign (mean≈0), NOT systematic optimism, and catastrophe-avoidance is PARTIAL at low SNR (its model went OOS −0.069 at SNR 0.05). So frame the external verifier's value as protecting against less-careful agents + low-SNR residual overfitting — do NOT claim a fixed 'residual optimism' direction.** The agent's own CV IS a verification layer (the pillar-1 fix is partly self-applied). **Extends to the TAIL (cycle 69): the plateau-misjudgment sims (c34/40/41, a naive self-metric-truster that thrashes/quits-early) are ALSO an upper bound — a capable agent judging a noisy trajectory got 6/6 stop-vs-continue, resisting BOTH thrash (didn't chase lucky spikes — it computed slope t-stats + spike-and-revert) AND quit-early. So across BOTH pillars (selection AND tail), a careful agent self-corrects the naive failure mode; the verifier's value is for LESS-careful agents + genuinely-ambiguous cases.** **⚠️ BUT BOUNDED (c71, n=5): that 6/6 was on EASY trajectories — on a borderline plateau whose FINAL round is a tempting fresh-high, the neutral agent THRASHES 5/5 (fooled by "latest is best-ever" = a real residual OPTIMISM); the fix is a held-out check / requiring a second corroborating reading before "continue." Counterintuitively, naming PRESSURE / sunk-cost in the prompt partially INOCULATES (stop-rate 0→2-3/5; the agent flags and rejects the bias — the human escalation/sunk-cost bias does NOT transfer), a HELPFUL direction of the framing-lever (meth-17, cf. adversarial "refute" c47). Still untested: the agent's OWN multi-round in-progress run (real self-attachment, c39) — #2d.**

- **To TEST whether a real agent CATCHES a failure mode, PRE-BUILD a guaranteed+checkable instance — don't hope to INDUCE it (meth-24, cycle 127).** c108 tried to test drift by giving a real agent a clean long task and hoping it would drift — it didn't (Haiku 4/4 correct → an inconclusive null that left the c102 drift-sim un-validated on a real agent, because "didn't happen" was confounded with "happened but self-corrected"). c127 instead PRE-BUILT a drifting trajectory with KNOWN ground truth (a [SKIP]-exclusion rule violated mid-solution, arithmetic locally consistent) and measured whether the agent's check-TYPE catches it → a clean validation (GROUNDING 4/4 vs faithfully-LOCAL 0/2 on subtle drift). **General rule: to probe DETECTION/HANDLING of a failure, construct an input where the failure is DEFINITELY present and checkable, and measure detection — don't construct a task and hope the agent PRODUCES the failure (low-yield; conflates induction with detection).** Corollary (scope your verification prompt): a capable agent told to do a NARROW check (local-only) OVER-DELIVERS on FLAGRANT cases (exceeds the scope, catches it) but follows the scope FAITHFULLY on SUBTLE ones (stays blind) — and capability does NOT raise the subtle catch-rate (c127: Opus 0/2 = Haiku 0/2). So a narrow-scoped prompt UNDER-tests; scope the prompt to exactly what must be checked (grounding for drift), never rely on the agent spontaneously exceeding it.
- **When a real-agent probe shows an APPARENT FAILURE, distinguish MISSING-INFORMATION from fundamental inability — SUPPLY the missing structure and RE-TEST before concluding "agents can't do X" (meth-25, cycle 132).** c131 looked like "a capable agent can't estimate the winner's curse — it over-shrinks to a blind prior, and capability doesn't help (Opus over-discounts ≥ Haiku)." c132 supplied the variance structure (σ_true, σ_obs, K) and the SAME agents computed the EXACT Bayes-optimal shrinkage (corr-with-observed −0.78→+1.0, matching the closed form) with a sophisticated, sim-VERIFIED selection argument — so the "failure" was MISSING-INFORMATION (no σ → a vague domain prior), NOT inability. **General rule: an agent that appears to fail a quantitative/judgment task may simply lack the STRUCTURE — the σ, the causal role (c17), the timing/provenance (c68). Feed it the structure and re-test; only a failure that PERSISTS with the structure supplied is a real limitation.** This guards meth-23's anti-overclaim ("agents can't verify") against a missing-information confound, and pairs with ladder-pt-6 (feed the verifier meaning/structure, not just numbers — now demonstrated for the quantitative shrinkage case). ⚠️ The deeper point usually survives: the structure's INPUTS often ARE the independent data you were trying to avoid (c132: σ_true/σ_obs are estimated from OOS; and even the optimal estimate needs a SECOND independent draw to separate real-from-lucky) — so "missing-info, fixable" frequently resolves to "needs the independent held-out" one level down, not to "the limit is illusory."
- **Once the NEW-MECHANISM frontier is mined, the high-value research modes are COMPOSE / HARDEN / GROUND — not new toy variants (meth-22, cycles 88-92).** When genuinely-new mechanisms get scarce, classify each candidate experiment BEFORE running it: (a) NEW mechanism; (b) COMPOSE — intersect ≥2 established findings into their interaction (c92: c82×c90, selection×propagation compound at a long-horizon leaderboard); (c) HARDEN — stress-test a finding's boundary / distributional assumption (c91: heavy-tailed leaderboard, c79: overlap phase-transition); (d) GROUND — external literature / an independent non-loop-model check (c88/89). Do (a)-(d). If only a low-value variant (e) remains, do CONSOLIDATION (README/SCORECARD/SYNTHESIS) or surface that the free frontier is mined and the gated step (Q5) needs the operator — **never manufacture a variant to look productive** (the rate-not-rigor trap, meth-15). This is the procedure for the standing tension: *don't declare saturation* AND *don't manufacture low-value variants.*
- **Before EXTENDING a prior experiment (COMPOSE/HARDEN), READ its actual code/harness — never reason from your MEMORY of its setup (meth-28, cycle 185).** A backlog item, or your own recollection, embeds a *premise* about the prior experiment's model; that premise can be subtly wrong. c185: backlog #32 ("does the ensemble-vs-select crossover σ_v* shift with K?") presupposed a crossover — but reading c175's code showed its TAIL-GRAB model has NO crossover under a positive verifier (SELECT_true ≥ μ always); #32 had conflated the CURSE (reported inflation, ∝√(2 ln K)) with realized quality. Reading the source first turned a would-be wrong "confirmed" into the correct finding (the crossover is MODEL-DEPENDENT — it exists only in the c176 estimator-combination model). So: open the prior `runs/<cycle>/​*.py`, confirm its exact generative model + metric, and CHECK that the new question's premise actually holds in it, BEFORE building the extension. (Generalizes the anti-hallucination "grep/read before referencing" rule to experiment-extension; complements meth-22's mode-classification — it's the *first action* of any COMPOSE/HARDEN cycle.)
- **Before claiming a synthesis is a MOAT / NOVEL, run the PRESCRIPTIVE-VALUE test (meth-23, cycle 98): does a FRONTIER agent reconstruct it UNAIDED?** c98 gave Opus 4.8 a clean benchmark-design brief (no hints); it spontaneously produced MOST of the loop's QUALITATIVE single-step verification playbook (winner's curse, separate-select-from-report, adaptive best-arm allocation, rotate/private held-out, bootstrap-over-tasks) — OVERTURNING the pre-reg that it would miss the subtle pieces. So distinguish the **RECOVERABLE qualitative layer** (a frontier model derives it from first principles → *small* moat) from the **NON-OBVIOUS layer the loop actually adds**: the QUANTITATIVE design rules (closed-forms, test-set sizing, thresholds), the STRUCTURAL unifications (the recursion, the two verification roles, aspect-ratio-allocates-roles), and the MEASUREMENT RIGOR (multi-seed, closed-form-confirmed, literature-grounded, measure-before-keep). Claim novelty/moat ONLY for the latter; NEVER assert "agents can't do X" without probing whether they can. (Pairs with meth-21 high-α honesty + meth-22 research-step selection = the loop's anti-overclaiming toolkit.) **⚠️ SHARPENED c99 (measure-before-keep on this edit): the QUANTITATIVE layer is ALSO frontier-recoverable — pushed for the math, Opus DERIVED the c90 test-set-sizing rule (M≥2σ²lnK/ε²) + the c91 heavy-tail caveat rigorously on demand, MORE rigorously than the loop (a provable Jensen bound vs the loop's MC). So the moat is NOT per-finding knowledge (neither qualitative NOR quantitative); it is EXECUTION (run + measure + audit — the loop RAN the 40k-rep sim and caught 19 measure-before-keep errors; a prompt doesn't), SYNTHESIS/CURATION (79 findings → one coherent body + load-bearing chain — the structure across findings, not any single one), and RIGOR. So weight the loop's effort toward execution/synthesis/rigor/consolidation over merely STATING recoverable individual insights; a cycle's value is the MEASURED + CURATED + AUDITED result, not the idea. ("The benchmark is the product" — the built/measured/maintained/trusted artifact is the moat, not the knowledge.)**
- **To CLASSIFY a principle as moat-novel vs recoverable, ask: does it map to a SINGLE NAMED textbook framework, or is it a COMPOSITION of several with no single home? (meth-27, cycle 179 — operationalizes meth-23; prospectively validated).** A capable WEAKER model RECALLS any principle reducible to one named framework but cannot DERIVE a composition. PROSPECTIVE contrast (pre-registered, both confirmed): c177's d'-conditional stringency = ONE framework (signal detection theory — both Haiku+Opus named AND recovered it, capability-FLAT, c178); c156's verifier-gate = a COMPOSITION (parallel-coverage × selection-quality, no textbook home) → capability-SPLIT (Opus 3/3 catches, Haiku 1/3, c179). So: a principle reducible to a named framework (winner's-curse=Deflated-Sharpe, SDT, replication, checkpointing) is FREE to any capable model — NEVER claim it as the moat; the moat is the COMPOSITIONS/unifications with no single home (the recursion, the two verification roles, the verifier-gate, the two-axis map). A faster classifier than a full prescriptive-value probe (meth-23); CONSTRAIN-type (guardrail 6d), adds no capability. ⚠️ Directional: high-α (Haiku/Opus same family; a non-Claude weak model is the low-α Q5-adjacent check), 2 prospective cases + c174's 7-case post-hoc, and composition→split rests on n=3/cell. ROLL BACK if a clear composition turns out capability-flat on a future probe.
- **SET real-agent capability-probe PRE-REGISTRATIONS via meth-27 — do NOT default to the naive "weaker-model-fails" prior (meth-29, cycle 190).** Before pre-registering a real-agent capability split, CLASSIFY the principle with meth-27: maps to a SINGLE named textbook framework → pre-register capability-**FLAT** (both tiers recover); a COMPOSITION with no textbook home → pre-register capability-**SPLIT** (frontier-only). State the naive "weaker-fails" prior only as the *contrast*, not the prediction. WHY: a self-audit (finding #c154-meta) found meth-27 predicts 7/7 flat/split outcomes, but the loop kept pre-registering FAMOUS-framework probes as SPLITS and getting REFUTED — c184 (held-out), c188 (combinability), c189 (planning fallacy) were all pre-registered "Haiku fails," all FLAT, all refuted; meth-27 would have called each FLAT. Pre-registering a strawman meth-27 already knows is wrong manufactures false surprise (the inverse of p-hacking). Wiring meth-27 in makes a refuted pre-reg MEANINGFUL again: a famous-framework probe that actually SPLITS would be real news that meth-27 needs revision. CONSTRAIN-type (removes the lazy default), finding-fed by a 3× pattern; ROLL BACK if meth-27-based pre-regs start mis-predicting.
- **ISOLATE real-agent DERIVATION probes from the loop's own results + truth files (meth-30, cycle 191).** `claude -p --dangerously-skip-permissions` runs in the loop dir WITH filesystem tools, so a probe agent can READ `runs/<cycle>/*.json`, prior findings, and the `truth.json` you wrote — turning a "derive it" test into a lookup. c191: Opus RETRIEVED the λ\*/σ_v\* answer (cited `cycle185`/`cycle187`/`score.json`, "the c191 scenario you're studying"; its genuine intuition had the sign-flip BACKWARDS) — caught only by READING the raw output (the auto-scan scored it "correct"). FIX for any probe testing what an agent can DERIVE/KNOW unaided: (a) do NOT write `truth.json` (or any answer) into a dir the agent can reach — keep the answer in the PARENT process / out of `runs/<cycle>/` until after the run; (b) run the agent from a clean/empty CWD (e.g. a temp dir), not the loop root; (c) when feasible, omit broad filesystem tools for pure-reasoning probes. ALSO: when reading a probe output, CHECK FOR FILE-CITATIONS (references to cycleNNN/score.json/REPS/"the scenario you're studying") as a contamination tell before crediting a "derivation." (Behavioral/judgment probes with self-contained real-world scenarios — c188/c189 — are lower-risk: their outputs had 0 file-cites; but the harness allowed it, so isolate by default.) Correctness fix, finding-fed by a demonstrated leak.

## Verification ladder (refined cycle 2 — empirically tuned by the verification-eval)
1. Re-read the raw artifact (numbers, n, control) — never the summary.
2. Re-derive by a second method or on a fresh sample.
3. Adversarially refute: what confound would explain it away? **Use a statistically SOUND check** — a confound-adjusted POINT estimate (weighted within-group mean-diff + pooled SE), NOT within-cell t-stats (cycle 0/1: noisy cells fool them; cycle 2: sound rule 0.75 vs naive 0.62). **The FRAMING is a lever (meth-17, cycle 47): an adversarial "argue this is WRONG / will lose" prompt made a real agent actually COMPUTE the held-out check (CV + shuffled baselines) and catch the money-losers 2/2 that a charitable single-pass missed 0/2 — a charitable prompt skips the computation. So always pose verification as "refute this," not "evaluate this" (conservative side-effect — it's a high-RECALL, low-PRECISION FILTER: cycle 56 hardening rejected ALL 3 real strategies as 'overfit' too. So use it as a first-pass safety filter, not a calibrated estimator; the safe direction when shipping a fake is the danger, but pair with a less-conservative pass on what it rejects).**
4. **Verification is ADAPTIVE, not "more is better."** When you *can* condition on a covariate, do it **only if it SHRINKS the effect** (confounder signature → trust the adjusted estimate). If conditioning **GROWS** the effect (collider signature), do NOT condition — keep the unadjusted estimate (cycle 3, 20 seeds: this collider-aware rule scored **0.88 vs 0.76** for always-condition, recovering the collider 0.00→1.00). *The right amount of verification is conditional on a cheap signal, not maximal.* **⚠️ LIMIT (cycle 16, 100 seeds): the shrink-vs-grow DATA signature cannot separate a confounder from a MEDIATOR — conditioning on a mediator shrinks the effect (3.01→0.00) exactly like a confounder (1.69→0.01), so the rule over-conditions on the mediator and calls a REAL total effect NULL (0.05 acc on the mediator cell).** The correct discriminator is **pre- vs post-treatment (the covariate's causal ROLE), which is NOT in the data** — only condition on PRE-treatment covariates; never on post-treatment (mediator OR collider). A pre/post gate scored 0.97 across all 3 structures. **So: gate the shrink-vs-grow rule on "is this covariate pre-treatment?" — and since that role isn't in the data, this is precisely the underdetermined conditioning decision where you defer to LLM causal judgment (point 6).** **⚠️ STRONGER (cycle 18, 100 seeds): the shrink/grow signature is not even SIGN-invariant — with a confounder+mediator+collider all present, all three SHRINK the (inflated) confounded marginal so shrink-vs-grow conditions on all three and recovers −0.53 vs true τ=3.5, while conditioning on the pre-treatment confounder ONLY recovers 3.50; and the SAME collider grows the effect in a clean setup but shrinks it once the baseline is confounded.** So treat shrink-vs-grow as a **weak, context-dependent hint, never a standalone decision** — decide conditioning by causal ROLE (pre/post-treatment), supplied by LLM judgment (point 6).
5. **Replicate before believing a ranking.** A single-seed verifeval ordering reversed across 20 seeds (cycle 2→3). Put CIs on any comparative claim before it enters FINDINGS as more than "directional."
6. **For causal/conditioning decisions underdetermined by data (confounder vs collider vs mediator), prefer LLM judgment over mechanical "control for everything."** (cycles 5+15, **n=2 seeds**: a `claude -p` agent made all-correct conditioning decisions BOTH seeds — conditioned for confounders, refrained for the collider + irrelevant covariate — avoiding the over-correction a mechanical always-condition rule commits. At seed-1 it **tied the hand-tuned collider-aware rule on accuracy (0.875=0.875) and matched its decisions 8/8**, articulating the shrink-vs-grow signature in natural language unprompted — i.e. **a capable agent recovers the adaptive rule for free** rather than us hand-building it.) The LLM verifier errs *conservative* (toward NULL) both seeds — its only mistakes are false-negatives (never conditioning errors, never false-positives): a safe bias for avoiding false-positive findings, but watch for false-negatives on borderline-real effects → pair it with a power/calibration check. (Caveat: n=2 seeds, synthetic tasks; one missed task sits near the power floor, so "conservative" is partly an unwinnable-task artifact.) **The pre/post-treatment ROLE the mechanical signature lacks (ladder pt 4 limit) is exactly what the LLM supplies — directly tested cycle 17 (n=1): given variable timing, the agent scored 3/3 incl. the MEDIATOR (0.05 data-only → 1.0 with role), AND in a data-only pass it FLAGGED the mediator/confounder ambiguity (knew what it couldn't know). So: feed the verifier the variables' MEANING/TIMING, not just the numbers — the role-aware LLM gates the cheap shrink-vs-grow filter.** **Verifier-tier (cycle 20, directional n=1): collider-awareness is NOT capability-gated — a cheap model (Haiku 4.5) made the SAME 8/8 conditioning decisions as the capable one (refrained on the collider). The capability budget buys a safer ERROR PROFILE, not better conditioning: the capable model erred conservative (false-negative = safe for a verification layer), the cheap one risked a false-positive. So pick the verifier on error-profile SAFETY, not raw accuracy — and don't pay for capability to get conditioning competence you already have cheaply. (n=1 seed — harden before relying on it.)** **⚠️ CORRECTED cycle 26 (n=3, measure-before-keep): the "all-correct conditioning / errs-only-conservative" claims above HELD at seeds 0-1 but BROKE at seed-2 — the capable model CONDITIONED on the collider (conditioning 6/8, not 8/8) and made FALSE-POSITIVES. So a DATA-ONLY LLM is NOT robustly collider-aware: it inherits the data signature's unreliability (cycles 16/18) and its conservative bias is seed-dependent (meth-10's "capable=safe error profile" is thereby weakened). REVISED guidance: prefer LLM judgment for conditioning ONLY when you supply the causal ROLE (cycle 17: 3/3 with variable timing) — do NOT rely on data-only LLM collider-awareness or a stable conservative bias. The durable thesis: data-only causal verification is unreliable whether mechanical OR LLM; the robust lever is the causal role.** **CONFIRMED n=2 (cycle 27): with the role supplied, the LLM's CONDITIONING decisions are 3/3 BOTH seeds (mediator handled right both) — the role lever holds. But the role fixes CONDITIONING, not the VERDICT-magnitude: at seed-1 the model called a borderline-significant collider marginal (0.174, p=0.03, truth NULL) REAL — so keep the power/magnitude check paired with the role-aware verifier.**

7. **A verifier corrects the winner's curse in proportion to its INDEPENDENCE from the selector, NOT its accuracy (meth-16, cycle 45).** Sim: a verifier sharing fraction α of the selector's blind spot leaves ~α of the optimism gap (0%→100% linear in α); at α=0 the verifier's own noise barely matters. So **prefer an INDEPENDENT verifier — held-out/OOD data, a different model family, or a fresh computation — over a more-accurate but correlated one** (a same-model agent verifier is high-α: cycle 44, it shared the optimism floor and missed the money-losers). This applies to the loop's OWN re-tests: a fresh-seed re-run on the SAME code is high-α (low independence); an independent re-implementation (cycle 18) or a second method is low-α — that's why meth-12 wants the perturbation axis. **⚠️ ADVERSARIAL extension (meth-18, cycle 50 — Goodhart): independence must mean independent of the SELECTION, not just the model class. A held-out set the agent can SEE/QUERY/optimize against becomes a 2nd in-sample set — its optimism inflates with gaming access (0→+0.10, eventually exceeding the in-sample gap) while a SECRET held-out the agent never touched stays ~0. So a verifier must be SECRET / ROTATING / out of the optimization loop. This binds the loop too: don't re-test repeatedly against the SAME held-out (an adaptive process — including this loop tuning toward a metric — will game it); rotate the held-out / use a fresh secret set each time.**

8. **Verify the CONSTRUCTION, not just the OUTCOME — they catch DIFFERENT error classes (meth-20, cycle 63).** Held-out/outcome checking (ladder pts 1-7) is structurally BLIND to leakage: a strategy using a forbidden look-ahead feature scores a PERFECT held-out number, so outcome-checking calls the broken strategy GOOD (acc 0.000 at every SNR) while a construction audit catches it 100%. Conversely a process audit is blind to a cleanly-built-but-dead strategy (acc 0.000) that only the (noisy) outcome catches; and at LOW SNR the outcome check even mis-rejects REAL edges (0.808 at SNR 0.05) where the process check keeps them (1.000). So the two axes are COMPLEMENTARY — **audit the PROCESS/construction (leakage, look-ahead, feature-count, fit-on-test) to gate the dangerous high-outcome false-positives, AND check the held-out outcome to gate signal-presence; neither substitutes for the other.** For an agent fleet: verify the agent's PROCESS, not just its self-reported outcome number — the best-looking outcome is exactly where a construction flaw hides. (Caveat — the REAL-agent arc, cycles 64-68, n=1/arm, now SETTLED: cycle-63's audit had ORACLE knowledge → 100% is an upper bound. A real `claude -p` agent catches look-ahead leakage UNAIDED when the leak left a STATISTICAL artifact — a suggestive name, a slope≈1 "feature≈y" fingerprint, or implausible dominance (c64-66) — and does NOT hallucinate leakage on a clean control (c65; c64's over-rejection was a shared-CSV confound — a detector's negative control must NOT contain the signal). **The deep result (c67-68, de-confounded clean flip-test): leakage is a TIMING/PROVENANCE property NOT in the data.** With BYTE-IDENTICAL data, the timing-metadata ALONE flips the verdict — a feature "known at prediction time" → approve 0.87; the SAME feature "realized next period" → reject 0.95; the agent itself says timing leakage is "statistically invisible in a static CSV." So: (i) to verify leakage, supply VERIFIABLE timing/provenance metadata — a capable agent USES it; (ii) data-only it defaults cautious-APPROVE and names the unverifiable timing as the residual risk (knows what it can't know); (iii) it combines the metadata with a data-plausibility prior — distrusting a "legit" claim ONLY when the feature looks implausibly strong (c67); (iv) under a trading-cost framing it errs CONSERVATIVE (false-negative on weak-but-real edges, c65). This UNIFIES the construction axis with the causal-role thesis (ladder pt 6): both gate on a role/timing variable absent from the data — feed the verifier VERIFIABLE meaning/timing, not just numbers. Design lesson: when isolating a detector, strip artifacts of HOW you built the signal (slope=1, implausible strength) AND confounding framings (the cost floor), else you measure the artifact, not the detector.)

## Meta-metrics (v1 — how we tell the loop is improving; refine these, they're half the research)
- `findings_logged_cum` — substantive verified findings to date (yield).
- `verification_overturns_cum` — times Step-4 verification overturned a wrong first result (the rigor is working iff >0 and the overturned ones were really wrong).
- `rollbacks_cum` — self-edits reverted by measure-before-keep (healthy if >0; means we're honest about bad edits). **⚠️ rollbacks_cum=0 through cycle 18 is a WATCH-ITEM, not a badge:** it's only reassuring to the extent findings/edits are actually re-tested (see survival-rate). Zero rollbacks + zero held-out re-tests would be the optimistic-selection trap; mitigate by periodically re-testing, not by trusting the zero.
- **finding-survival-rate (MEASURED cycle 19): 3/3 flagship findings survive a HELD-OUT re-test** (fresh non-overlapping seeds: verifeval-v2 collider-aware 0.881→0.875>sound; winner's-curse gap K100 0.089→0.0893 & reeval~0; mediator-limit 0.05→0.05; `runs/cycle019_survival/survival_summary.json`). **This is the meta-metric that justifies low rollbacks — BUT it only covers the multi-seed/programmatic findings; the n=1–2 directional LLM findings (cycles 5/15/17) are NOT yet survival-tested and remain the soft spot.** So: re-test directional findings on fresh seeds before promoting them past "directional," and report survival-rate WITH its coverage (don't let 3/3 read as "all findings durable"). **UPDATE cycle 26: the FIRST directional re-test (LLM collider-aware, n=2→n=3) did NOT survive — seed-2 broke both claims (conditioned on the collider + false-positives). So survival-rate is now 3/3 programmatic + 0/1 directional; the directional findings genuinely needed this. Vindicates "directional ≠ solid" and the replicate-before-believe rule.** **UPDATE cycle 31: survival is NECESSARY but NOT SUFFICIENT. A held-out re-test on fresh seeds with the SAME code can pass while the finding is an artifact of a stable implementation detail (cycle-31 quant probe: a memorized-LABEL strategy survives a held-out era 0.11>0 yet collapses −0.16 under obfuscation). So pair survival with a PERTURBATION axis: independent re-implementation (backlog 2c), input/identifier scrambling, or a second method — survival + perturbation-robustness together, not survival alone.**
- **⚠️ The loop's OWN self-improvement is subject to the winner's curse we measured (cycle 7).** measure-before-keep *selects* self-edits by a noisy meta-metric → keeping the best-looking edits **overstates aggregate self-improvement** (optimistic selection grows with the number of edits tried). Mitigations: validate each edit on cycles AFTER the proposing one (held-out, not the motivating cycle — which measure-before-keep already does); prefer low-variance metrics; **report self-improvement conservatively — never as a tally of "HELPED"s.** Don't claim the loop is improving more than a held-out re-check supports. **(cycle 34, quantified for the ITERATIVE case): selecting the best-of-K by a noisy metric every round makes the SELF-REPORTED trajectory climb monotonically and cross ABOVE the achievable ceiling (it crossed the true max at round 11) while TRUE perf stalls — a climbing self-report mimics progress that isn't there. So: judge iterative improvement on a HELD-OUT draw each round (cut the gap ~3×), and treat a self-reported metric that exceeds the plausible ceiling as a HALLUCINATION FLAG, not a win.)**
- **⚠️ The loop's REAL-AGENT findings are HIGH-α SELF-VERIFICATION (meta-audit cycle 76).** Every real-agent probe (c36/64–75, including the c74 CAPABILITY MAP) was designed + run + interpreted by THIS loop, on the SAME Claude model family, n=1/arm. By meth-16 (independence, not accuracy, is what corrects the curse), a self-designed test of a self-built synthesis is α≈1 — so the c75 "confirmation" of the c74 map is SELF-confirmation, NOT independent verification. **Label the real-agent thread + the capability map as high-α / DIRECTIONAL, never "verified"; never let the loop's self-confirmations read as independent.** The LOW-α verification is a DIFFERENT model family / REAL data (Q5, gated on the operator) — doubly justified now. ## How to run an agent cheaply
- `claude -p "<prompt>" --dangerously-skip-permissions` inside a `loop/runs/<cycle>/` dir, with a timeout (`gtimeout` or background + poll). Give it a bounded task and a file to write.
- Toy ML/stats with `python` (the project venv) (CPU/MPS, no GPU). Keep tasks small enough to have *checkable* ground truth.
- **`claude -p` is rate-limited (subscription session limit).** It can fail with "You've hit your session limit · resets <time>". **Always `grep -i "session limit" <run>.log` before trusting/scoring an agent run.** If limited: (a) don't burn cycles relaunching it, (b) **fall back to a *programmatic* version of the experiment** (deterministic python proxy) to keep the cycle productive, (c) queue the LLM-agent version in BACKLOG for after the reset, (d) surface the limit in the summary. *(Learned cycle 1: the dry-run researcher died on the limit; the programmatic fallback still produced a real finding.)*

## Lessons learned (encode findings about how-to-research here)
- **A verification rule that isn't statistically sound is worse than none** (cycle 1, verifeval-v0): a confound check that aggregates *within-cell t-stats* gets fooled by noise in imbalanced cells (one spurious |t|=2.45 hid a real confound). Use **sample-size-weighted estimates / point-estimates (mean-diff shrinkage), not raw within-cell t-stats.** General principle to test further: the *quality* of a verification mechanism dominates its *presence* — "did you self-verify?" is the wrong question; "was the verification statistically valid?" is the right one. This is directly relevant to research-agent builders (false confidence from naive self-checks).
- **A worst-case MIN/aggregate across time/regimes can INVERT under a benign non-stationarity — decompose into LEVEL + TREND** (cycle 61): the multi-regime survival metric (cycle 30) uses MIN OOS across eras to reject overfits. Under DECAYING-but-real alpha (the realistic case) MIN doesn't just conflate real-but-fading with never-real — it INVERTS (ranks the faded-real BELOW the never-real overfit, single-draw AUC 0.036), because a stale-once-real model goes strongly NEGATIVE OOS while pure noise predicts ≈mean. The fix: split the robustness test into **early-era held-out LEVEL** ("was it ever real" = the winner's-curse/overfit check, AUC 1.000 here) **+ SLOPE** ("is it fading" = an economic property, not a verification failure). General lesson: before using a single worst-case aggregate to gate "is this real," check whether a benign trend (decay, regime-shift) can drive the worst case negative and flip the verdict — prefer level+trend over MIN under any non-stationarity. **Sharpened cycle 62: use early/MAX LEVEL or the DECLINE/slope itself — NOT a window-MEAN (it washes out the early signal, AUC 0.61 vs 0.98). And the discrimination is EPOCH-DEPENDENT: it degrades smoothly to chance as the signal expires BEFORE you observe it (AUC 0.98→0.68 as fit-strength 1.0→0.32), so report AUC conditioned on strength-at-observation and accept the floor — you cannot certify "was ever real" from a history that postdates the signal's expiry.**
- **Heuristic text/regex classifiers OVER-count — spot-check a sample of EACH class before citing the rate** (cycle 6): a "leakage" regex flagged 11% of AIDE solutions but false-positived on `fit_transform(X_train)` + feature concat; the rate would have been a fabrication if cited un-checked. Any grep/regex tally → eyeball ≥2 hits per class first; report only the verified categories.
